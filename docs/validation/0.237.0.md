# PeleF 0.237.0 validation record

## Scope

This milestone qualifies configure-time selected-mechanism dispatch,
rank-neutral checkpoint creation, intentional stop, and transactional restart
for the established sparse MPI reactive AMR 1D patch-tree lifecycle. Fixed
magic/schema 1 remains byte-for-byte. A selected call uses schema 2 under the
same magic.

Selected MPI EB AMR is not included.

## Persistence and MPI contract

The selected writer requires the canonical bundle SHA-256, generated
`explicit` or `implicit` integrator, mechanism species count, finite
nonnegative normalized bundle-order composition, and finite original
composite integrals whose species components close to density. The reader
validates those records plus the complete patch-tree body, finite geometry and
clock, every raw conserved species density as nonnegative, EOS-recoverable
physical state, positive finite stored temperature, terminal marker, and end-
of-stream in private candidates before publishing. Failed reads preserve the
caller solution and baseline, and invalid writes do not replace an existing
checkpoint.

The checkpoint stores physical hierarchy state but no communicator size or
owner map. Restart rebuilds distribution for the current rank count. Every
rank must agree on the complete selected context before initialization or file
creation, and the generated integrator reaches every sparse chemistry half-
step.

## Focused compatibility and failure gates

The unit checkpoint gate covers schema-2 round trip, baseline round trip,
fixed/selected cross-schema rejection, bundle/integrator/composition mismatch,
trailing content, truncation, invalid baseline write non-destruction, and
failed-read rollback. It also rejects negative density, negative species
density including an EOS-tolerance-scale `-4.0e-11` value, species closure
failure, and nonphysical selected writes without replacing the prior file.
MPI units prove explicit-integrator forwarding and collective rollback on one,
two, and four ranks. Separate process gates mutate bundle, integrator,
composition, species order, baseline, density, raw species, near-floor raw
species, closure, temperature, and geometry; require rank-context consensus;
and reject input/output aliasing before mechanism loading.

The final-source MPI Debug focused set passes 37/37 tests in 18.48 s. It uses
the CMake-selected `/usr/bin/mpiexec` and links OpenMPI's `mpi_f08` ABI 40; a
different MPICH launcher found earlier on `PATH` was not accepted as evidence.
An independent Luna Max read-only audit reports `blocking=0` after the raw
near-floor species gate.

## Clean Release qualification

An empty-environment, tests-disabled GNU 13.3.0 Release build with OpenMPI,
the pinned full-H2/O2 selected bundle, and no SUNDIALS or Cantera reference
support installs successfully. All 39 installed ELF files are byte-identical
to the build-tree executables, have non-executable stacks, carry no RPATH or
RUNPATH, and have no unresolved runtime dependency. The audit finds only the
expected OpenMPI ABI-40 sonames and no oneAPI or `libmpi.so.12` contamination.
See [the clean Release install evidence](evidence/0.237.0-clean-release-install-audit.txt).

The installed fixed executable completes the one-rank reference. The installed
selected executable completes one-, two-, and four-rank references, writes a
one-rank first-step checkpoint, and independently resumes it on two and four
ranks. Every final file is byte-identical, and the installed checker pins the
same output and checkpoint hashes. Eleven independent context/payload
corruptions plus the path-alias case all fail under `/usr/bin/mpiexec -n 1`
without changing their inputs or creating output. See
[the installed restart evidence](evidence/0.237.0-installed-selected-sparse-mpi-amr-1d-restart.txt).

## Qualification boundary

This evidence establishes deterministic configure-time selected sparse MPI
AMR 1D continuation across one, two, and four ranks. The bundle SHA-256 is
provenance rather than payload authentication. It does not establish selected
MPI EB AMR; runtime mechanism loading; CFD CVODE dispatch; crash-atomic or
scalable I/O; thread safety; performance; detailed-fuel physical validity; or
external PeleC field parity.

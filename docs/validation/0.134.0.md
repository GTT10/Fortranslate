# PeleF 0.134.0 validation record

## Scope

This milestone adds a geometry-only 2D EB patch-tree topology whose depth,
parent count, and child count are selected at runtime. It also adds a
transactional whole-tree rebuild operation without introducing numerical field
storage into the topology type.

## Automated evidence

The established EB multilevel unit constructs two separated root children,
refines both branches, and adds a fourth level below only the second branch.
The topology must validate the root plus three refinement relations, ordered
parent links, flattened child offsets and local-child indices, per-level patch
counts, refinement ratios, complete EB geometry consistency, and sibling
separation.

The rebuild gate first commits the three-level-to-four-level change, then
requires the identical plan to report an exact no-op. A deepest child that
references a nonexistent parent must reject while preserving the accepted
four-level topology and reporting no change.

Qualification head `a23d1a2` is covered by ordinary CI run `32947214361` and
MPI CI run `32947214268`. GNU Fortran Release and bounds/FPE-checked Debug passed
the complete 208-test serial regression. The MPI workflow also passed all
established one-, two-, four-, and eight-rank gates in both configurations.

## Qualification boundary

The new tree contains geometry and patch metadata only. Arbitrary-depth
numerical field containers, conservative state migration, MPI ownership,
physics recursion, timestep selection, checkpoint I/O, and dynamic tagging
remain separate work. Existing qualified numerical paths retain their fixed
two-level multipatch or strictly nested three-level interfaces.

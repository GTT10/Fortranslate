# PeleF 0.146.0 validation record

## Scope

This milestone retains each owner tile's computed coarse x-flux rows and
uniquely owned y-faces after a sparse transport Euler stage. For every child,
only intersecting face fragments route directly from those tile owners to the
child owner. The receiver verifies complete face coverage, initializes the
compact coarse register, and accumulates the coarse contribution locally.

The root-to-child state context no longer carries a serialized flux register.
Fine ratio subcycling, fine-flux accumulation, child-local reflux, cumulative
support ordering, and final root-row scatter retain their established
arithmetic and transactional publication rules.

## Automated evidence

For every qualification child, the MPI application requires the compact state
context plus coarse interface-flux value count to be positive and strictly
smaller than the former complete root state, temperature, and x/y-flux bundle.
Exact traffic is derived from every remote root-tile/child face intersection
for both SSPRK2 Euler stages, in addition to the established state-context and
corrected-support messages.

The application retains exact owner work, transfer counts, limiter minima,
serial root/child field parity, public-clock accounting, scheduled regridding,
periodic-edge finite bands, and late-failure rollback. Qualification head
`3dc22b2` is covered by ordinary CI run `32992544996` and MPI CI run
`32992545021`. GNU Fortran Debug and Release builds pass. OpenMPI one-, two-,
four-, and eight-rank gates pass in Release and bounds/FPE-checked Debug
configurations, and both workflows pass the complete 208-test serial
regression.

## Qualification boundary

The root physics owner still receives and assembles the complete temporary
root state, temperature, and x/y-flux result from the distributed tile
computation. It remains responsible for exterior-state extraction, cumulative
corrected-support merge, boundary closure, and final row scatter. Direct
root-tile state/support routing is the next milestone. Hydro is unchanged.
This milestone qualifies ownership, numerical parity, traffic accounting, and
rollback behavior; it does not claim a measured speedup.

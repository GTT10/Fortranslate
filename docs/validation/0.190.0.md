# PeleF 0.190.0 validation record

## Scope

The public fixed three-level EB AMR lifecycle can schedule an opt-in dynamic
root-to-middle patch and restart both actual refined patch descriptors.

## Automated evidence

The public offset-hotspot unit gate enables `dynamic_parent_regridding`,
requires at least one regrid, requires the accepted parent bounds to differ
from the configured seed, validates both nested descriptors, and retains the
three-level composite conserved vector. The installed dynamic hotspot case
must write a middle rectangle whose dimensions differ from the configured
20-by-20 seed and a valid finest rectangle crossing the embedded boundary.

The uninterrupted, checkpoint-stop, and restarted dynamic cases use limited
linear prolongation and schema 4. The checker requires the stored policy flag,
a moved parent descriptor, a non-seed finest descriptor, a positive regrid
count, topology-derived CSV sizes, and root/middle/finest field parity between
the uninterrupted and restarted processes.

GNU Fortran Debug and Release qualification run identifiers are recorded in
the pull request before merge. The complete MPI chain remains required because
the shared driver and configuration modules serve serial and sparse-MPI
arbitrary-depth paths. Fortran parsing, line length, Python syntax, version
consistency, and `git diff --check` are also required.

## Qualification boundary

The fixed-depth public path retains one middle and one finest rectangle.
Multiple dynamic parents, fixed-depth MPI ownership, and backward reading of
schema-3 dynamic three-level checkpoints are not claimed.

# PeleF 0.220.0 validation record

## Scope

This milestone adds an installed serial constant-volume reactor for one
normalized mechanism selected at CMake configuration time. It loads the
generated NASA7 and elementary-reaction arrays, maps an input composition by
exact species name, and advances the existing adaptive implicit generic
reactor for 2--32 species.

The selected runtime is compiled separately from `pelef_core` and the
committed generated mechanisms. This prevents Fortran module and linker-symbol
collisions when the selected bundle declares the pinned full-H2/O2 names.

## Input and startup contract

- every real-valued control, temperature, pressure, and mole fraction must be
  finite, with positive time controls, tolerances, temperature, and pressure;
- `initial_time_step` lies within the minimum/maximum bounds and
  `output_interval` is not below the minimum; a scheduler-clipped final
  fragment shorter than the minimum is accepted only without a further
  adaptive reduction;
- `composition_count` is 1--32, active names are nonblank and nonduplicate,
  and every unused name/value slot is blank/zero;
- composition names match bundle species exactly and are normalized after
  mapping into bundle order;
- lexical `.`, repeated-separator, and reducible-`..` aliases between input
  and output paths are rejected;
- the generated loader must return the declared species and reaction counts,
  valid reaction structures, molecular-mass-balanced reactions, and a common
  NASA7 temperature interval containing the initial temperature;
- generator validation independently checks element and molecular-mass
  balance from normalized thermo composition records;
- the CMake build helper requires schema 1, explicit generated-interface
  names, and complete thermo/transport arrays; a generator-compatible legacy
  kinetics-only bundle is rejected with a dedicated configure diagnostic;
- the unknown-species and out-of-range-temperature regressions require a
  nonzero exit, the expected diagnostic, and no CSV artifact.

bundle order. The first output row still has exact expected mass fractions
`Y_H2=8/9` and `Y_H=1/9`. Across five rows to `1.0e-7 s`:

- density drift and reported/independent closure error were exactly zero;
- maximum relative internal-energy error was
  `2.4690138609422258e-16`;

  `1.1102230246251565e-16`;
- temperature changed by `1.7862895539899455 K` and the largest mass-fraction
  change was `9.0888365840757768e-5`;
- the maximum molar rate was `2.9080980887785248e1`, while instantaneous mass
  and atom source residuals were exactly zero;
- two independent runs produced the same CSV SHA-256,
  `fd12f4cf429aa6017f34a0ac92a7ed4435fab0ff1ffeafe2e1855ceaea5d82f4`.
  The same signature was reproduced in all five regression configurations.

A separate scheduler regression ended at exactly `1.000005e-7 s` after a
`5.0e-13 s` final fragment, below its configured `1.0e-12 s` adaptive floor.
It produced all four scheduled rows and passed the same independent
conservation, activity, and finite-output checks.

The pinned selected full-H2/O2 application and the fixed
`pelef0d_h2o2_full` application each accepted 5,461 implicit steps and 36,754

The selected and fixed outputs had that same signature in all five regression

## Build and installation evidence

A clean Release build with tests disabled selected
`mechanisms/h2o2_full.json` and source-checked
`mechanisms/h2o2_cantera.yaml`. It generated, built, and ran both
`pelef_mechanism_probe` and `pelef0d_selected`. The fresh install contained 19
executables: the 17 default serial targets plus those two selected targets.
Every installed file was byte-identical to its build-tree artifact and all 19
ELF files had non-executable stacks. A separate tests-disabled build with no
selected bundle built the fixed reactor without creating the selected runtime
target.

Fresh default Release and MPI Release installs contained 17 and 28
executables. All 45 installed files were byte-identical to their build-tree
artifacts and had non-executable stacks. The eleven installed MPI executables
had no RPATH, RUNPATH, Intel, or oneAPI dynamic tags; clean-environment `ldd`
resolved every dependency; and the installed two-rank 15-component halo smoke
test passed.

The focused Debug selected-mechanism set passed 19/19 tests, covering
configuration validation, generator and CMake build-contract validation, both
ABI probes, fixture execution and checking, short-final-fragment scheduling,
repeat-run identity, startup failures, selected full execution and checking,
exact fixed/selected parity, generated-source cleanliness, project contracts,
and executable-stack status.

## Qualification boundary

The generated loaders feed the shared generic elementary-reaction
backward-Euler integrator. The generated production kernel supplies output
rates in `kmol/(m^3 s)`; there is no generated callback integration ABI. The
supported build-helper chemistry remains schema 1 with complete NASA7 and
primitive transport records plus the existing elementary, three-body, and
Troe falloff forms with at most 32 species. The lower-level generator retains
a separate legacy kinetics-only mode that is not a build-helper input.

This evidence is structural, conservation, determinism, and same-code-path
parity evidence. It is not runtime YAML/JSON loading, selected-mechanism CFD,
transport, AMR, EB, or MPI dispatch; it is not CVODE/SUNDIALS parity or a
performance result; and it is not physical validation of a new or detailed
fuel mechanism against PeleC, Cantera, experiment, or literature.

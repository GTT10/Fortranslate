# PeleF 0.50.0 validation record

## Scope

This milestone connects deterministic MPI AMR patch ownership to the first
real patch-tree physics operator: owner-only elementary H2/O2 chemistry with
collective acceptance, authoritative state broadcasts, hierarchy
synchronization, and global rollback.

## Automated evidence

`pelef_mpi_amr_patch_1d` initializes the same four-level `1/2/3/2` reactive
tree on every rank. Its eight patches use the `0.49.0` cell-weighted owner map.
Each rank reports exactly its local owned-patch count and their communicator
sum is exactly eight, proving that chemistry is neither duplicated nor
omitted as the communicator changes.

The distributed elementary H2/O2 chemistry result is compared with the serial
patch-tree chemistry operator across every conserved state, temperature,
narrow ghost, and wide ghost value. Relative difference remains below
`5e-13`. Chemistry measurably changes the reactive field while composite mass,
three momenta, and total energy remain within `3e-10` of their initial values.

For rejection, a deep patch is corrupted only on its owner and synchronized.
The owner failure occurs after earlier patches have advanced. Logical-AND
acceptance rejects the operation on every rank, returns zero accepted local
patch calls, and restores state, temperature, ghosts, time, and counters
exactly to the owner-synchronized backup.

The MPI workflow executes the owner map, halo, chemistry, and rollback gates
with 1, 2, 4, and 8 ranks in both GNU Fortran Release and bounds-checked Debug
builds. The complete serial regression suite remains enabled separately.

Branch runs 32696553826 (complete serial Debug/Release suite) and 32696553889
(complete MPI Debug/Release suite) passed for implementation commit `2ee26c4`.

## Qualification boundary

Chemistry executes on owners alone, but patch storage remains replicated.
Hydro and molecular transport still use the serial patch-tree recursion;
distributed stage halos, shared fine/fine fluxes, reflux ownership, sparse
rank-local storage, and regrid migration remain future integration work.

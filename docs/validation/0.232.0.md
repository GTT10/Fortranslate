# PeleF 0.232.0 validation record

## Scope

This milestone qualifies checkpoint creation, intentional stop, and
transactional restart for the established configure-time selected serial,
static, exactly-two-level reactive EB AMR 2D application. Fixed calls retain
checkpoint schema 3 byte-for-byte. Selected calls use exclusive schema 4,
which binds continuation to the normalized mechanism bundle, generated
chemistry policy, and bundle-order initial composition.

Dynamic regridding, three-level, multipatch, and MPI EB AMR persistence are
not included.

## Persistence contract

A fixed caller supplies no selected metadata and reads or writes only schema
3. A selected caller supplies all of a canonical lowercase 64-digit bundle
SHA-256, `explicit` or `implicit` integrator, and finite nonnegative normalized
mole-fraction vector with one entry per mechanism species; it reads or writes
only schema 4. Partial context and both cross-schema directions fail.

Schema 4 inserts these records after the common header and before the existing
species/configuration/patch/state body:

```text
SELECTED_CONTEXT
<bundle SHA-256>
<chemistry integrator>
<species count>
<normalized bundle-order mole fractions>
```

No restart target is published until the complete context, geometry,
embedded-wall identity, numerical controls, patch, clock, coarse/fine fields,
and terminal marker validate. Detailed failure context is propagated through
the shared application.

## Unit and startup gates

The two-level driver unit gate covers selected schema-4 round trip, incomplete
write and read context, fixed-reader/schema-4 and selected-reader/schema-3
rejection, changed bundle SHA, changed integrator, changed normalized
composition, malformed context marker, truncated context, invalid negative
composition, complete failed-read rollback, and preservation of an existing
valid checkpoint after a rejected write.

The selected front end rejects every pairwise lexical alias among the input,
coarse output, fine output, checkpoint, and restart paths before opening any
of them. Unsupported dynamic/three-level/multipatch gates remain active.

## Qualification boundary

This evidence establishes selected-mechanism provenance, deterministic serial
static two-level continuation, actionable compatibility rejection, and
transactional rollback. The bundle digest does not authenticate the checkpoint
body. Finite physically consistent payload tampering, crash-atomic file
replacement, schema conversion, dynamic/three-level/multipatch or MPI EB AMR
restart, scalable I/O, runtime mechanism loading, CFD CVODE, detailed fuels,
thread safety, performance/scaling, external PeleC field parity, experiment
validation, and the repository license remain open.

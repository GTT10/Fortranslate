# PeleF 0.222.0 validation record

## Scope

This milestone replaces the optional CVODE selected-reactor singleton with an
opaque, generation-checked context API. Up to 64 SUNDIALS 7.2.0 CVODE BDF
contexts may remain live and be advanced in any sequentially interleaved
order. The native adaptive implicit backend remains the default. SUNDIALS is
still optional, exact-version, official-Fortran, and static-only; no fixed
application or selected mechanism probe gains that dependency. Configuration
also verifies a double-precision ABI and rejects synthetic single- and
extended-precision headers.

The public handle owns no C pointer or Fortran mechanism object. It carries
only a private registry slot and generation. A stable C-interoperable token
with the same values is installed through `FCVodeSetUserData`; callbacks
validate it before resolving the private Fortran registry. The registry owns
all mechanism arrays, reduced/full work state, SUNDIALS resources, time,
temperature guess, cumulative budget, statistics, and failure state.

## Multi-context lifecycle evidence

The dedicated unit gate uses the generated two-species `H2/H` fixture in two
different states:

- A starts at mole fractions `[0.8, 0.2]`, `1000 K`, and `101325 Pa`; `H2` is
  the dependent closure species.
- B starts at mole fractions `[0.1, 0.9]`, `1200 K`, and `202650 Pa`; `H` is
  the dependent closure species.

Each state first runs alone with a fixed requested-output schedule. Two live
contexts then run those same schedules in an interleaved order. A is finalized
while B remains live and B performs one further advance. For both states, the
final mass fractions and temperature are bitwise equal to standalone, and all
six CVODE counters are exactly equal. Same-handle double finalization succeeds.

A separate pair gives context A one internal step and forces its CVODE advance
to fail. Its caller mass fractions and temperature remain byte-unchanged and a
second advance is rejected by the failed-context quarantine. Context B then
advances successfully and reports positive independent statistics before the
pair is finalized in the opposite order.

The test copies a live opaque handle, finalizes its owner, creates a replacement
in the freed slot, and attempts cleanup through the old copy. Generation
validation rejects and clears the stale copy; the replacement still advances.
Finally, the test initializes all 64 advertised slots, rejects a 65th request
without assigning its handle, releases the registry in reverse order, and
idempotently finalizes the rejected empty handle. This capacity gate also
proves that a failure after initial thermodynamic validation leaves `ok` false.
A full Valgrind leak check of this lifecycle reported no definite or indirect
loss after the fixture's caller-owned arrays were explicitly deallocated.

A fresh tests-disabled Release configuration selected the pinned full-H2/O2
bundle and enabled the static CVODE backend. It built and installed 19
executables. In a cleared environment, the installed mechanism probe, native
reactor, and CVODE reactor ran in separate clean directories and reported
version `0.222.0`. The two reactor CSV hashes matched the values above. All 19
installed files were byte-identical to their build-tree artifacts and had
non-executable GNU stacks. The installed selected reactor had no RPATH,
RUNPATH, unresolved library, or dynamic SUNDIALS dependency; `ldd` listed only
the system `gfortran`, math, C, and GCC support libraries.

The lifecycle executable was also run under Valgrind after the final adapter
changes: 8,448 allocations and 8,448 frees, zero bytes in use at exit, and zero
reported errors. The forced one-step CVODE failure emits the expected vendor
diagnostic and is accepted only after caller rollback, quarantine, and peer
isolation checks pass. A destroy-error injection shim is not part of this
milestone; any real nonzero destroy status is terminal, reports the first
failing routine, completes best-effort ordered cleanup, and invalidates the
public handle rather than attempting an unsafe retry.

## Qualification boundary

This is deterministic lifecycle and numerical evidence for sequentially
interleaved serial contexts. It does not permit simultaneous calls from
threads, callback reentrancy, or shared registry mutation without external
serialization. It is not a performance or scaling result. Runtime YAML/JSON
loading, selected chemistry in CFD/transport/AMR/EB/MPI, sparse linear
algebra, sensitivities, mechanisms above 32 species, new rate families,
detailed fuels, experiment parity, and production release remain open. The
repository license remains an explicit owner decision and release blocker.

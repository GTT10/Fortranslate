# PeleF 0.208.0 validation record

## Scope

This milestone adds versioned checkpoint/restart to the qualified serial,
static, single-patch, two-level general-EOS 3D AMR hydro application. The file
captures the full hierarchy and continuation history and is accepted only
after complete thermodynamic, solver, mesh, physicality, and synchronization
validation.

## Automated evidence

- `unit_amr_reactive_3d_config` rejects invalid checkpoint controls and any
  checkpoint/restart path that collides with coarse or fine CSV output;
- `unit_amr_reactive_3d_checkpoint` checks exact state/metadata round trip,
  recovered-temperature agreement, unsynchronized and temperature-inconsistent
  write rejection, and transactional solver-mismatch/truncated-file rejection;
- `regression_amr_reactive_3d_checkpoint_stop` writes a synchronized
  full-H2O2 hierarchy at coarse step four and intentionally stops;
- `regression_amr_reactive_3d_restart` restores that hierarchy and advances to
  the original final time;
- `regression_amr_reactive_3d_restart_compare` requires byte-for-byte equality
  with both uninterrupted coarse and fine CSV outputs.

The public 8^3 coarse plus 8^3 ratio-two fine case restores at coarse step

## Qualification boundary

This record qualifies same-schema, same-precision, serial checkpoint/restart
for the periodic, inviscid, PCM, static, strictly interior, single-patch,
two-level 3D AMR hydrodynamic application. It does not qualify distributed or
cross-rank restart, dynamic topology, chemistry/transport AMR state, EB, file
checksums, atomic/scalable storage, cross-toolchain bitwise identity, schema
migration, or whole-application PeleC parity.

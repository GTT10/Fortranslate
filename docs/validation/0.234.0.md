# PeleF 0.234.0 validation record

## Scope

This milestone qualifies configure-time selected checkpoint creation,
intentional stop, and transactional restart for the established serial,
static, exactly-three-level reactive EB AMR 2D hierarchy with one patch per
level. Fixed static three-level magic/schema 3 and fixed dynamic three-level
magic/schema 4 remain byte-for-byte contracts. A selected static call uses
schema 4 under the static magic.

Selected dynamic three-level, multipatch, dynamic-parent, and MPI EB AMR
persistence are not included.

## Persistence contract

The selected writer requires the canonical bundle SHA-256, generated
`explicit` or `implicit` integrator, mechanism species count, finite
nonnegative normalized bundle-order composition, and finite initial composite
integrals. It writes `SELECTED_CONTEXT` and `COMPOSITE_BASELINE` records before
the established static three-level body.

The reader derives the expected schema from the fixed/selected call contract.
It validates context, baseline, species, geometry, wall and numerical policy,
nested patches, clock, diagnostics, all root/middle/finest state and
temperature fields, EOS consistency, and the terminal marker in private
candidates. No caller-owned restart target is published until the complete
file validates. Restart restores the original composite baseline before
advancing.

## Qualification boundary

This evidence establishes deterministic serial selected static three-level
continuation and generated-context provenance. The bundle SHA-256 does not
authenticate the checkpoint body. It does not establish selected dynamic
three-level, multipatch, dynamic-parent, or MPI EB AMR persistence; runtime
mechanism loading; CFD CVODE dispatch; crash-atomic or scalable I/O; payload
authentication; thread safety; performance; detailed-fuel physical validity;
or external PeleC field parity.

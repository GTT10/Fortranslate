# PeleF 0.233.0 validation record

## Scope

This milestone qualifies configure-time selected checkpoint creation,
intentional stop, and transactional restart for the established serial,
dynamic, exactly-two-level reactive EB AMR 2D application with one fine
patch. Fixed schema 3 and selected static schema 4 remain byte-for-byte
contracts. Selected dynamic calls use exclusive schema 5.

Selected three-level, multipatch, dynamic-parent, and MPI EB AMR persistence
are not included.

## Persistence contract

A fixed caller supplies no selected context and reads or writes schema 3. A
selected static caller supplies the complete generated context and reads or
writes schema 4. A selected dynamic caller supplies the same context and reads
or writes schema 5. The context is the canonical bundle SHA-256, generated
`explicit` or `implicit` integrator, mechanism species count, and finite,
nonnegative, normalized bundle-order composition.

Schema 5 retains the schema-4 `SELECTED_CONTEXT` record and the established
transactional two-level body. Between them it adds a `DYNAMIC_BASELINE` record
with the finite `nvar`-component initial composite integrals. The body stores
dynamic policy, actual patch bounds, regrid cadence and count, clock,
diagnostics, geometry, state, temperature, and the terminal marker.
Static/schema-5 and dynamic/schema-4 reads fail without fallback. No
caller-owned restart target is published until the complete file validates.

## Qualification boundary

This evidence establishes deterministic serial selected dynamic two-level
continuation, generated-context provenance, explicit topology-class
compatibility, and transactional rollback for one fine patch. The bundle
digest does not authenticate the checkpoint body. Finite physically
consistent payload tampering, crash-atomic replacement, schema migration,
three-level/multipatch/dynamic-parent or MPI EB AMR restart, scalable I/O,
runtime mechanism loading, CFD CVODE, detailed fuels, thread safety,
performance/scaling, external PeleC field parity, experiment validation, and
the repository license remain open.

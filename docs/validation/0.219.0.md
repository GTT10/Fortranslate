# PeleF 0.219.0 validation record

## Scope

This milestone connects a normalized mechanism bundle to the CMake build
graph. An explicitly selected bundle is regenerated in the build tree,
compiled in an isolated Fortran target, linked to a bundle-declared ABI probe,
and optionally installed. It also adds a directional finite-difference gate
for the energy-constrained full-H2/O2 reactor Jacobian.

## Build contract

- `PELEF_MECHANISM_BUNDLE` selects one normalized JSON bundle;
- `PELEF_MECHANISM_SOURCE` optionally requires the supplied source basename
  and SHA-256 to match the bundle at configure and generation time, and is
  rejected if no bundle is selected;
- CMake reads the module, loader, kernel, Jacobian, thermo-loader,
  transport-loader, and symbol-prefix names from JSON rather than assuming the
  fixed H2/O2 interface;
- generated Fortran is written only below the build directory and compiled in
  an isolated static library and module directory;
- `pelef_mechanism_probe` loads and checks thermo, reactions, primitive
  transport, production rates, and the Jacobian through those declared names;
- the selected executable is installed only when selection is explicit, and
  is registered as `unit_pelef_selected_bundle` when tests are enabled;
- the default test graph compiles a separate two-species, one-reaction fixture
  and requires nonzero production-rate and Jacobian activity.

## Direct evidence

- Debug and Release fixture configurations generated, compiled, linked, and
  ran the probe as `PASS (2 species, 1 reactions)`;
- a clean Release configuration with tests disabled selected
  `mechanisms/h2o2_full.json` plus its pinned YAML, built and installed the
  probe, and ran as `PASS (10 species, 29 reactions)`;
- a mismatched elementary YAML was rejected during configuration with the
  source SHA-256 diagnostic;
- a tests-enabled selected configuration registered and passed
  `unit_pelef_selected_bundle`;
- the source-check CMake test covers an exact positive check and deliberately
  wrong hash and basename rejections;
- touching copied bundle and source inputs caused Ninja to rerun CMake and the
  source-checked generator before relinking the selected probe;
- the generator accepts a 128-character equation, keeps every generated line
  at or below 100 characters, and compiles the result with GNU Fortran;
- 63-character bundle interfaces and long provenance values keep both the
  generated module and configured probe at or below 100 characters per line
  and compile with GNU Fortran;
- invalid leading-underscore identifiers, dependency-module names, imported
  identifiers, probe/generated-module namespace collisions, and an oversized
  derived Jacobian name are rejected before source generation;
- the reduced reactor Jacobian checks all nine basis directions plus one mixed
  direction; its maximum directional relative error was
  `1.1803040536098200E-08` against a `2.0E-4` limit.

## Qualification boundary

Selection is configure-time ABI qualification, not runtime mechanism loading
or application dispatch. The selected bundle must already satisfy schema 1 and
the generator's existing NASA7, gas-transport, elementary/three-body/Troe, and
32-species boundaries. A supplied source is checked as an immutable input; it
is not reparsed during this path. Without `PELEF_MECHANISM_SOURCE`, the bundle
itself remains the provenance authority.

This record does not qualify general YAML/CHEMKIN input, NASA9, PLOG,
Chebyshev, SRI, Lindemann-only falloff, custom orders, detailed hydrocarbons,
runtime fixed-application dispatch, CVODE parity, external PeleC field parity,
or physical validation.

## Local qualification results

The local toolchain was GNU Fortran 13.3.0, CMake 3.28.3, Python 3.12.3,
Cantera 3.2.0, and `/usr/bin` Open MPI 4.1.6. The five-configuration regression
matrix passed 1,440/1,440 tests:

| Configuration | Result | Real time |
| --- | ---: | ---: |
| Debug | 281/281 | 770.83 s |
| Release | 281/281 | 244.53 s |
| Debug + Cantera 3.2.0 | 286/286 | 770.44 s |
| MPI Debug | 296/296 | 790.95 s |
| MPI Release | 296/296 | 253.80 s |

The matrix ran concurrently and is therefore not a serial performance
measurement. Review then hardened generated-line width and identifiers,
configure-dependency tracking, probe failure sequencing, and the Jacobian
test without changing production solver sources or committed generated
Fortran. All five configurations were reconfigured and rebuilt. The final
affected set passed 8/8 tests in each ordinary/MPI configuration and 9/9 in
the Cantera configuration, for 41/41 post-review gates. Both committed H2/O2
mechanism modules remained byte-clean under the hardened generator.
After the independent long-name review, the final generator/probe/Jacobian/
source-contract subset passed another 32/32 gates across the same five
configurations. The selected fixture and pinned full-source probe tests also
passed 2/2 after rebuilding.

Fresh default Release installs contained 17 serial and 28 MPI executables.
All 45 installed files were byte-identical to their build-tree artifacts and
had non-executable stacks. The eleven MPI executables had no RPATH, RUNPATH,
Intel, or oneAPI reference, clean-environment `ldd` resolved every dependency,
and the installed two-rank 15-component halo smoke test passed.

A separate clean tests-disabled selected-bundle install contained the 17
ordinary executables plus `pelef_mechanism_probe`. All 18 files were
byte-identical to the build tree and had non-executable stacks. The selected
probe SHA-256 was
`3bb4f9ab54fe79110056f89664447a73769720406d126480a618397626d1e99d`
in both locations and the installed probe repeated
`PASS (10 species, 29 reactions)`.

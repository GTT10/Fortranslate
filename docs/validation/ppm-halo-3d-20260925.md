## Implementation

`compute_reactive_ppm_halo_ctu_fluxes_3d` accepts exactly four supplied ghost
layers on each side. It reconstructs normal states on cells 0:n+1, uses the
six dt/3 corner solves and three dt/2 final solves, and returns all physical
faces including index zero. Reconstruction pencils reach -3:n+4. Corner
and final solves are bounded to their consumers; no periodic donor mapping
occurs in this API. Far corner padding outside these pencils is ignored.
Fluxes and the limiter diagnostic publish only after every solve succeeds.
The existing periodic implementation is unchanged.

`advance_reactive_boundary_hydro_3d` now accepts `characteristic_ppm`, fills
four layers with existing reservoir/Mach/wall/outflow and pressure-target
helpers, then advances physical cells with one CTU step. Optional full-face
or upper-face flux outputs and the integrated boundary ledger use these
same fluxes. Failed flux construction or final EOS recovery preserves U/T
and leaves flux/ledger outputs zero. The full reaction/transport/hydro
library composition now dispatches physical-boundary PPM.

The regular application input still restricts PPM to periodic boundaries.
AMR/MPI stepping has not yet been connected to this new halo API. As in the
periodic implementation, conservative EOS transverse correction differs
from the pinned PeleC separate primitive-pressure update; this does not
establish reference pressure parity.
